# Django Техническое задание

## Требования

- Python 3.11 и выше
- git

## Установка и запуск

1. Скачать проект на [GitHub](https://github.com/meumeu21/tz-django)
2. Создать виртуальное окружение (venv):

```bash
python -m venv venv
source venv/bin/activate (или .\venv\Scripts\Activate.ps1 в Windows)
```

3. Перейти в желаемый проект:

```bash
cd (название папки проекта)
```

4. Установить зависимости через:

```bash
pip install -r requirements.txt
```

5. Создать файл настроек .env:

```bash
cp .env.example .env
```

6. Сгенерировать секретный ключ и вставить его в .env SECRET_KEY:

```bash
python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())"
```

8. Создать суперпользователя (указать логин, почту, пароль по-своему желанию):

```bash
python manage.py createsuperuser
```

9. Создать базу данных:

```bash
python manage.py migrate
```

10. Запустить сервер

```bash
python manage.py runserver
```

## URL-short - сокращение ссылок

Форма сокращения ссылок до 6-значного кода и страница с таблицей ранее сокращенных ссылок.

| Адрес | Что там |
|-|-|
| / | Форма сокращения ссылки, последняя созданная ссылка с кнопкой копирования и история из 5 предыдущих ссылок (хранится в сессии) |
| /list-links/ | Список всех ссылок, поиск по исходной ссылке или коду, сортировка, пагинация |
| /<код> | Перенаправление на исходную ссылку |
| /admin/ | Админка для просмотра и удаления ссылок |

### Особенности

- Повторное сокращение одной и той же ссылки возвращает существующую ссылку
- Код из 6-символов [A-Za-z0-9] генерируется через secrets
- Адрес нормализуется: ссылка приводится к нижнему регистру
- Разрешены ссылки только http и https
- Запрещены ссылки с логином и паролем в адресе, ссылки на сам сервис, на внутренние ip-адреса
- Есть лимит сокращения ссылок: 10 в минуту, 100 в сутки с одного ip
- Счетчики ограничения хранятся в памяти процесса (LocMemCache)

### Настройки

| Переменная | Описание |
|-|-|
| SECRET_KEY | Секретный ключ Django, нужно создать его перед запуском проекта |
| DEBUG | Режим отладки |
| ALLOWED_HOSTS | Домены через запятую (например 127.0.0.1, localhost) |
| HTTPS | С HTTPS=True редирект на https |
| BEHIND_PROXY | Сайт стоит за прокси (nginx), IP берется из X-Forwarded-For, протокол берется из X-Forwarded-Proto |

С HTTPS=True команда runserver не работает. Чтобы проверить работу без отладки, нужно поставить DEBUG=False и запустить сервер с флагом insecure: python manage.py runserver --insecure
